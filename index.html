Mechanism design

Slot reservations

Uncapped competition meant many providers downloading the same content for a lucrative storage request could DDoS the client that created it, and potentially centralise storage hosting to the most resourced providers (eg data centers). Slot reservations fixed this by first capping the number of competing providers and second by using the value of a transaction to signal intent. Designing this feature included an adversarial analysis covering six named attacker classes and a written record of every mechanism that did not make the cut. Read the design →

Protocol design

On-chain marketplace

An on-chain storage market where clients pay providers to store data durably: threat modelling and mitigation, incentive and collateral design, then planning, implementation, spec writing, testing and exploit preparedness. At the heart of the client-side implementation was a sales state machine. After log crawling the devnet and noticing issues, I put together a per-state recoverability analysis giving every state in the sales machine a defined outcome under crash, power loss and asynchronous cancellation.

Gas economics

10× cheaper state restoration

Two contract data structures to store storage request state were benchmarked for their gas efficiency. The Worst-case slot-freeing fell from 3,115,596 to 302,584 gas. The report priced the difference in euros at live rates and ended the debate. Read the analysis →
